# Scalable object rendering and depth reconstruction

## Ownership and current paths

Presentation consumes copied viewer-authorized instances; simulation/headless remain independent. RenderWorld prepares a render-owner index once per accepted immutable snapshot. It caches previous full entity-generation matches, then reuses those indices during indexed interpolation instead of repeating a binary lookup for every render and shadow pass. Lookup by explicit entity identity retains the existing public behavior. New sessions clear previous matches; stale ticks cannot replace current state. No cached source outlives the two existing snapshots.

Contiguous groups of 32 instances receive conservative swept bounds. Positions span previous/current copies; a sphere encloses all intermediate rotations and scale interpolation, and vegetation includes its ground pivot and bounded wind sweep. Invalid group bounds fail open. Small snapshots use individual culling. Remaining instances still pass their original visibility, vegetation, frustum, asset and effect-admission checks. Shadow passes test their own frustum. There is no occlusion feedback, hidden-world query or speculative last-frame visibility reuse. Groups are based on snapshot order rather than spatial sorting; widely scattered identities can reduce the benefit, while correctness stays conservative.

Index arrays grow with snapshot size. A burst above 65,536 instances is released on the next smaller snapshot. Warm constant-size preparation and rendering reuse arrays. The index uses about four bytes per retained previous match and 25 logical bytes per retained cluster. These are managed payloads, not GPU memory. Existing frame-indexed instance uploads and fence retirement remain unchanged. SimpleInstanceRenderer accepts clusterCulling: false as an explicit constructor comparison/fallback path; normal clients enable it on all quality tiers without requiring a new GPU feature.

Existing projected-size LOD, 12% hysteresis, profile diameter scales, compiled unit/building/foliage LOD IDs, reduced wreck silhouettes and mechanical blending are retained. Render resolution changes preserve reference-display geometry thresholds. Runtime meshes are loaded lazily by compiled stable asset ID when an admitted LOD first needs them; inactive mesh buffers remain cached until session disposal. This is a finite catalog/session cache, not asynchronous mesh eviction. Texture tiers retain supplied mip policies. Terrain retains the bounded 128-chunk residency policy and fence-owned resource retirement. Missing content follows established geometry/material fallbacks; cosmetic decals skip missing resources. No authoring file is loaded during gameplay and no asset format changes.

## Reconstruction and optional GPU decisions

At world scale below one, the single composition draw reconstructs four display-linear scene samples using their existing world depths. Weights reject contributions that differ from the nearest sample's depth, with a bounded relative tolerance and normalization. Fog, exposure, ACES and spatial AA still apply through the existing sample path. Native overlay depth uses the nearest world depth; selection, commands and UI retain native output dimensions. Native scale preserves the original shader path. There is no new target, texture, resource stream, jitter or history allocation.

This spatial technique prevents cross-surface color mixing at tested depth edges. It cannot recover geometry smaller than the world-resolution pixel and may trade smooth silhouettes for firmer edges. Transparent vegetation/particles inherit opaque scene depth, so their reconstruction is approximate. Continuous motion and full-match art acceptance remain separate from fixed-state readbacks.

Temporal reconstruction was evaluated against current composition ownership: there are no per-pixel motion vectors, object-motion/deformation history, disocclusion confidence or validated history-reset contract for camera cuts, session changes, resize and exposure. Adding jitter/history alone would produce an incomplete temporal path. The tested depth-guided spatial path is the selected implementation; temporal reconstruction stays deferred until those prerequisites and a measured fidelity benefit exist.

ExecuteIndirect was evaluated against measured workloads: repeated rendering already uses indexed instancing, with four strategic draws in the 1,000-object reference and 39 batches for a synthetic 1,000-posed-unit workload. CPU work includes pose evaluation, material/LOD admission and instance packing, which indirect submission alone would not remove. A conservative CPU grouping path has a measurable isolated benefit without compute/UAV buffers, indirect command signatures or additional synchronization. ExecuteIndirect and GPU occlusion are deferred until draw recording or visibility is demonstrated to dominate representative sustained workloads.

Graphics probes Options7 mesh-shader and Options5 raytracing support once at device construction. GraphicsDeviceInfo.Advanced reports query success separately from support. Failed/unsupported probes preserve the baseline renderer; available features do not automatically enable a path. DXR and mesh shaders are not gameplay requirements. Microsoft contracts: [mesh shader options](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/ns-d3d12-d3d12_feature_data_d3d12_options7), [indirect drawing](https://learn.microsoft.com/en-us/windows/win32/direct3d12/indirect-drawing). Active profile/hardware identity still gates performance comparisons; informational Advanced probes are excluded so older otherwise matched manifests remain comparable.

## Diagnostics and reproduction

InstanceRenderDiagnostics adds ClusterTests, RejectedClusters, ClusterCulledInstances and InstanceBoundsTests. InstanceSubmissionMetrics adds SnapshotIndexBytes. RuntimeMaterialDiagnostics adds LoadedMeshCount and ResidentMeshBytes, counting unique cached vertex/index payloads rather than driver allocations. Reference captures already include submission metrics, copied visibility/LOD counts, completed-fence CPU/GPU pass distributions, allocations, native dimensions and adapter memory budgets. Texture bandwidth and GPU utilization percentages are not exposed and are not inferred from frame timings.

## Qualification limits

The baseline is fresh master e30b397a33e1bc9386be91e4a1b85898081448a4. Native object-culling images match it exactly across the four moving-camera reference cases. In the isolated CPU fixture, 5,000 fully culled instances changed from p50 439.4 microseconds to 3.9 microseconds in the first current cohort and 5.9 microseconds on the final source, with zero sampled allocations. This is a bound on that stage, not a generic game speedup. Representative native runs have variance and retained regressions beyond 15%; overall before/after frame performance remains unqualified. The first comparer attempt also rejected the newly added informational capability metadata; the compatibility correction is covered by report tests without ignoring adapter, driver, active profile or workload changes.

Available hardware tiers comprise one NVIDIA workstation laptop GPU and the software adapter; no midrange or integrated hardware measurement is invented. The debug layer was unavailable. Repeated fixed-state pixels and synthetic pan poses do not establish continuous-motion flicker, frame pacing or physical-display acceptance. No sustained 60 FPS, raytracing benefit, asynchronous mesh streaming or temporal-history quality is claimed.

The final rendering/package source is 703aaf89f092e832e8d6830a023074fa3169d026. Its full Release suite passes 1,916 tests with nine skips and zero failures; build has zero warnings/errors. Architecture covers 42 projects. The current-metadata bound hardening has targeted regression coverage; it does not change the fixed reference images. Snapshot index preparation for 1,000 copies measures p50/p95/p99 69.7/127.0/161.9 microseconds with zero warm sampled allocations. Final fully-culled p50/p95/p99 is 5.9/7.9/33.4 microseconds, versus baseline 439.4/772.3/990.1. The isolated median reduction is about 98.7%; full-frame native performance stays unqualified because of the retained variance/regression results.

The clean-source development package passes two-publish reproducibility, qualifies 492 assets, starts from an extracted install with 1,000 extra development instances, and produces two scaled Medium reference images matching the prior source pixel/PNG hashes. The separate headless run completes 16 ticks with 10,000 lightweight entities and no pending commands; it has no active gameplay systems, so it is not a large battle simulation test. Hardware cohorts contain eight-repeat native reference captures across Medium camera sweeps and Low/High/Ultra zooms. Software requests Ultra/75% resolve to Low/Quarter textures with native overlays and two matching readbacks.

Scaled Medium composition observations are 0.769 ms for repeated units versus 0.697 ms in the baseline, and 0.368 versus 0.366 ms for the industrial scene. This single pair is a cost observation rather than a performance gate or art approval. Depth weighting uses a 5% remaining-depth tolerance with a 0.00001 normalized-depth floor; shallow distant depth discontinuities and transparent content can still blend. No additional target or history payload is allocated.
