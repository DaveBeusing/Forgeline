# Production surface masters

The physical material set has twenty-four native 4096 x 4096 lossless PNG
masters: Base Color, tangent Normal and packed ORM for the shared sixteen-cell
Directorate/world atlas and seven terrain families. These are independently
authored periodic surfaces, not enlarged versions of the historical sources.
`build/Author-ProductionSurfaces.py` reproduces them with numpy and Pillow.
All randomness has fixed seeds. Historical sources remain editable references.

## Shared object surfaces

The five [industrial building production kits](IndustrialBuildingProduction.md)
reuse these exact masters, atlas cells and compiled mip chains. Their component
exports add geometry and dedicated LOD/state representations without any new
texture allocation, channel convention or material ID.

The atlas preserves the existing four-by-four UV identities: painted armor,
structural steel, rubber, canvas; glass, warnings, concrete, heat-treated steel;
worn armor, vents, wood, mineral rock; conifer, scrub, grass, service panels.
Metal panels include recessed joints and flush fasteners. Canvas has woven
relief; rubber has recessed tread; wood has grain and board joints; foliage
uses botanical stems, needles, leaves and blades. Height and wear fields drive
the corresponding normal, ambient occlusion and roughness data. Dielectrics
have zero metallic response; sensor glass is smooth, dark and nonmetallic.
Paint exposes metal only at authored worn regions. Base Color has no lighting
or cast shadows baked into it.

All object materials that use the atlas now use its matching atlas Normal.
The compiler derives BC7 textures at 2048 Base Color, 1024 Normal and 512 ORM.
Terminal atlas mips remain 128 x 128, or 32 texels per cell. Existing UV insets
protect adjacent cells. Runtime limits are explicit, not inferred from source
dimensions. The texture chains occupy 5,586,944 + 1,392,640 + 344,064 =
7,323,648 bytes. This is a texture allocation budget, not total GPU memory.

Production BC7 sources explicitly choose `textureCompressionQuality: balanced`.
The historical textures retain the default `best`. Large detailed normal maps
made clean best-quality encoding prohibitively slow for routine authoring
validation. Both settings preserve format, channel semantics and resident size.
The compiler validates the setting, includes it in cache identity and keeps
encoding single-threaded and deterministic. The normal-direction regression
uses a varying tangent field, a six-degree maximum decoded error, repeat-build
equality and quality-change cache invalidation. This numeric tolerance is not
a substitute for visual review of the authored surfaces.

## Enforced production allocation budgets

The twenty-four compiled physical texture chains allocate exactly 51,364,204
bytes: 7,323,648 for the atlas and 44,040,556 for terrain. The material
completeness test reads the compiled payloads and enforces this exact sum and
the twenty-four-map count. The original nineteen-map 26,448-byte budget
remains separately enforced.

The old 3 MiB compiled/4 MiB resident gameplay limits described the tiny
prototype sources. The production window qualification now bounds compiled
gameplay textures at 56 MiB, allowing container/UI/effect overhead above the
measured 53,008,312-byte catalog footprint. The native scene has a 64 MiB peak
resident texture limit for the physical maps, control masks, UI and effects.
Observed production reference runs allocate 52,187,924–52,707,564 texture
bytes. Splash/intro textures retain their separate 3 MiB limit; draw,
descriptor, sample-count, binding and resource-lifetime gates remain enforced.
These are texture allocation limits, not a total-VRAM or frame-rate guarantee.

`build/Refine-ProductionMeshes.py` authors small manufactured edge bevels
while preserving outer bounds, component UV orientation, pivots and stable
asset IDs. Unit LOD0, articulated tank turret, building LOD0 and supported prop
sources get sibling `_production.gltf` sources. Original source meshes remain
available. Existing LOD1/LOD2 and collision sources are unchanged; normal
gameplay retains their deliberately inexpensive role silhouettes. The
extractor's non-box topology remains intact. Bevels are 3.5% of the smallest
component extent. Tangents are generated by the existing importer.

Run `build/Author-UnitRunningGear.py` after the bevel pass to author faceted
wheels, tracked belts with visible road wheels and hollow weapon barrels in
the existing rubber/hot-metal component regions. The six unit families and
articulated turret retain original bounds and socket positions. This pass
requires freshly bevelled input; the prescribed authoring order is explicit.

## Terrain

Seven complete material families cover dry dirt, cracked earth/mud, rocky
scrub/grass, ash/industrial ground, concrete, bedrock and crushed gravel.
Bedrock and gravel have independent aggregate scale and fissure fields.
Periodic macro variation, aggregate and microdetail use the same physical
fields across maps. Concrete has joints and pore relief; mud has shrinkage
cracks. Scorched ground uses a darker ash material factor. These surfaces do
not encode gameplay identities solely in roughness.

Each terrain Base Color remains RGBA8 at 1024 because the CPU terrain profile
also samples it. Each Normal/ORM is BC7 at 512 with a full semantic mip chain.
Resident budget is 44,040,556 bytes for seven complete sets. Terrain normal
Y follows the existing tangent-space convention; normals are renormalized
during runtime-size and mip generation. The existing terrain macro splatting
and layer selection continue to apply. Control maps remain lossless data.

Production terrain covers 24–32 metres per tile: 32–42.7 runtime Base Color
texels per metre, 128–170.7 source texels per metre. This replaces the old
80–160 metre coverage without raising texture memory; macro layer blending
still operates at world scale. The shared atlas
has 512 runtime Base Color texels per cell; density on individual components
depends on their established UV layout and world scale. No uniform density
claim is made for the whole object set. Runtime caps require camera review
before raising them, especially for strategic views.

## Qualification

### Directorate material separation and fittings

See [material qualification](DirectorateMaterialQualification.md) for per-family
review, native camera evidence, measured cost and explicit acceptance limitations.

`build/Author-DirectorateDetails.py` follows the bevel, running-gear and mechanical
partition passes. Existing mechanical ranges and sockets are retained; appended
fittings use bounded static ranges, while scout sensor glass shares radar motion.
It derives seven LOD0 siblings from retained production sources: tank access
hatches, scout observation/sensor glass, truck windscreens and cooling grilles,
cargo straps, supply service vents, Command Core observation glass, factory
portal framing and plant heat exchangers. The pass asserts identical outer
bounds, retains the original position/normal/index prefixes and uses the same
material slot. It changes neither sockets nor collision assets. Added geometry
is 396 triangles across the seven sources, not per visible instance. Reduced
unit geometry is retained. The three selected building families remap broad
upward grille faces to painted roof surfaces at every existing LOD; dedicated
vents retain their material. Their LOD1/2 triangle counts stay unchanged.

Intact paint, warnings, rubber, canvas, glass, concrete, wood, rock and vegetation
are dielectric. Painted cells expose metallic substrate only through their
authored wear mask; roughness and reflectance use the same mask. Structural
steel uses a lighter neutral reflectance to separate it from rubber and dark
gunmetal. Glass no longer inherits metal-panel joints or fasteners. Base Color
remains sRGB, Normal/ORM linear, with ORM = AO/roughness/metallic. No light or
cast shadow is baked into these changes, and no emissive channel is added.

The atlas retains its 4x4 identities, 0.018 UV inset, runtime caps and terminal
128-pixel mips. At the smallest mip the inset is 2.304 texels, versus 36.864
Base Color texels at mip zero. Fittings use the same inset and single material
batch. Surface sources are deterministic mathematical authoring and fittings
are repository-authored geometry under the repository license; there is no
third-party source material. The existing 7,323,648-byte atlas allocation and
51,364,204-byte physical texture allocation are unchanged.

Acceptance remains zoom-specific: at 120m inspect glass/armor/rubber separation,
functional fittings, tangents and supported attachment silhouettes; at 420m
retain cab/cargo, gun/sensor and building-role separation without relying on
subpixel surface detail; at 1000m retain stable reduced silhouettes and state
indicators, without spending geometry on invisible fittings. LOD3/impostors
require measured benefit and are not introduced. Static reference images do
not qualify continuous zoom popping or sustained moving-camera shimmer.

`build/Author-IndustrialProps.py` follows the bevel authoring pass and replaces
seven prop sources with functional detail: ribbed closed drums, hollow flanged
pipes, slatted pallets with feet, fences with posts and rails, pole-mounted
industrial lamps, faceted mineral rocks and clustered rubble. It retains each
original outer bound and UV/material cell convention. Their inexpensive
reduced LOD meshes remain available for normal/strategic views.

The source catalog contains 437 stable assets. Asset compilation and runtime
qualification must pass before client review. The production master test
checks native dimensions, semantic color spaces, explicit caps and mip policy;
existing material completeness tests verify all physical mesh dependencies
and LOD material identities. General mesh authoring asserts unchanged outer bounds. The dedicated tank source
extends its cosmetic track bottom to the unchanged normalized ground plane;
[Main Battle Tank production](MainBattleTankProduction.md) records that decision.

Use the reference qualification matrix in
[RTS visual qualification](RtsVisualReferenceQualification.md). Data checks do
not establish visual acceptance: screenshots, terrain/foliage aliasing and
LOD-transition review, exact 4K output and controlled performance/total-VRAM
qualification remain separate acceptance work. No 60 FPS guarantee follows
from the texture budget. Roads/bridges keep their current production geometry;
this change does not add animation, skeletons, unique wreck models or LOD3.

The [modular environment kit](ModularEnvironmentKit.md) reuses these surface
masters and one material per LOD. Minerals use cell 11, timber 10, foliage 13,
concrete 6, steel 1 and warnings 5. No texture/material or alpha-card family is
added. New normals/UVs compile to tangents through the existing pipeline.


The four [operational building families](OperationalBuildingProduction.md)
also reuse these masters, atlas-cell insets, sRGB Base Color and linear
Normal/ORM channels. Source geometry adds external windows, manufactured
roofs/vents, generators/transformers and concave receivers without new maps or
material records. Compiler-generated tangents, BC7 caps and complete mip chains
retain existing resource contracts.

The [five industrial building families](IndustrialBuildingProduction.md) reuse
these same surface masters, atlas insets, sRGB Base Color and linear Normal/ORM
channels. Family geometry changes neither texture/material counts nor compiler
mip policy. Exported UVs/normals compile to orthogonal tangent frames; each
runtime assembly retains one material section. Native per-case residency and
resource binding results are recorded in the linked production report.

The [three logistics building families](LogisticsBuildingProduction.md) reuse
the same structural material and Base Color/Normal/ORM masters across dedicated
LOD and state geometry. No additional texture/material, sampler policy or atlas
layout is introduced. Their catalog qualification has 437 assets: 254 meshes,
56 textures and 127 materials. Native binding/residency and matched camera
measurements are recorded with the logistics capture evidence.

The [infantry and battlefield families](InfantryBattlefieldProduction.md) reuse
these masters and channel/mip conventions. Armor, canvas, glass, rubber, tools,
weapons, worn wreck panels and exposed concrete/rebar use the existing inset
atlas cells. No texture/material record is added.

The [four combat/support vehicles](CombatSupportUnitProduction.md) reuse these
masters without new texture/material records. Beveled armor, chassis steel,
rubber wheels/tracks, cab/sensor glass, cargo canvas, supply hardware and cannon
surfaces use the existing inset atlas cells, sRGB Base Color and linear Normal/ORM.
The integrated qualification contains 492 assets (309 meshes, 56 textures and
127 materials). Dedicated unit and logistics traffic captures report zero mesh
fallbacks and texture-binding failures; human surface/art acceptance remains open.

The optional [procedural CPU atlas producer](ProceduralPbrProduction.md) preserves the existing atlas and runtime budgets in isolated, verifiable source generations. Production promotion and art approval remain explicit; see its qualification report.
